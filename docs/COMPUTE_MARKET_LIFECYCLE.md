# COD 算力市场：业务闭环与责任边界

> 本文记录现有 V1“申请 + 人工报价”实现。新的奇点算力对标版采用独立全屏架构，开发与合并请以 [COMPUTE_MARKET_V2_DESIGN_SPEC.md](./COMPUTE_MARKET_V2_DESIGN_SPEC.md) 为准；统一计费以 [CARD_HOUR_SETTLEMENT_SPEC.md](./CARD_HOUR_SETTLEMENT_SPEC.md) 为准。V1 只作为兼容和数据迁移来源。

## 用户侧模块

算力市场在 Web、Desktop、Android 与 iOS 共用同一套界面和控制面 API，包含四条业务线：

- 租算力：选择已核验的 GPU 参考配置、镜像、卡数与预计卡时；库存、交付时间和兼容性以正式报价为准。
- 上架闲置卡：登记设备、地域与可用条件，审核产权、卡况、网络和机房条件后再上架。
- 第三方托管：登记机架空间、功耗、带宽、设备情况、结算偏好和 SLA 要求；COD 只做需求撮合与过程记录。
- 显卡分期：收集设备和期数需求，后续由有资质的合作机构独立审核、签约。

“我的算力”展示申请记录和三个汇总视角：我的资产、托管设备、设备租赁。汇总只统计用户已经接受报价且进入交付、运行或完成阶段的记录，不把咨询或被拒绝请求当作资产。

## 报价与履约状态机

```text
已提交 -> 联系中 -> 待确认报价 --用户接受--> 已确认 -> 部署中 -> 运行中 -> 已完成
                                \--用户拒绝-----------------------> 已关闭

已确认 / 部署中 / 运行中 -> 待用户处理 -> 部署中或运行中
任一尚未完成的人工阶段可按允许的状态迁移关闭
```

- 管理员只能在“联系中”创建正式报价，必须填写最终卡时数、有效期和条款；系统内报价不再使用人民币金额。
- 报价状态、正文和卡时数原子写入请求的 JSONB 载荷，并留下不含联系方式或条款全文的审计摘要。
- 管理员不能代替用户把“待确认报价”推进到“已确认”。只有申请所属租户和用户可以接受或拒绝。
- 接受过期报价、重复处理、跨用户处理、跳状态或基于旧状态并发更新都会被服务端拒绝。
- 用户接受后才进入部署；这一步表示接受 COD 记录的报价，不等同于第三方合同已经签署或设备已经交接。

## 第三方托管责任边界

COD 不接收、不保管设备，不代签机房合同，不代替托管商作 SLA 承诺，也不代为结算。现场验机、设备清单、保险、门禁/监控、故障响应、赔付、账期和退出搬迁须由设备方与第三方托管商书面确认。管理员后台用于查看申请人信息、记录沟通和发送报价，不应被用作合同或资产登记系统。

## 卡时

系统内所有商品和服务只使用卡时结算，原人民币标价迁移成卡时后数值不变，例如 `¥64.60` 改为 `64.60 卡时`，订单就扣 `64.60 卡时`。`1 卡时` 的人民币购买成本为 `¥1.002`，其中千分之二平台服务计提已经包含在购卡单价中，不再另收手续费，也绝不能再乘到商品卡时价上。人民币只能单向购买卡时，卡时不能兑回或提现人民币；卡时可在 COD 平台内交易和转让，交易前后都只记卡时。内部以千分之一卡时的整数存储；扣减按到期时间优先，管理员测试账户不扣卡时但仍记录免扣审计。人民币只用于通过外部渠道购买卡时及财务对账。

## 发布验收

- API：验证输入上限、租户/用户归属、报价过期、并发预期状态和审计记录。
- 管理员：可搜索申请、查看联系方式和托管参数、复制联系方式、发送报价、按允许状态推进。
- 普通用户：可提交四类需求、查看本人记录、接受/拒绝有效报价，且无法读取或处理他人请求。
- 客户端：四端检查窄屏、长表单滚动、软键盘、返回、刷新、冷启动和断网错误路径。
- 生产：必须另行接入真实库存、第三方合同、支付/发票、设备验收和 SLA 系统；当前人工撮合流程不能宣传为自动成交或 COD 自营托管。
